## The six decisions, as implemented

1. **Score observations separate from provisions.** New top-level
   `score_definitions[]` / `score_observations[]`. Each observation
   carries version, dimension, scale, nullable `value`, `status`
   (`unreviewed | unknown | reviewed_absence | provisional_value |
   reviewed_value | not_applicable | conflicted`), `source_scope`,
   `review_extent`, `basis_provision_ids` (must belong to the same
   version) and `comparability_note`. The library hardcodes **no**
   dimension labels (test-proven) and computes **no** composite;
   `build_public_views_v03` always withholds all score observations
   (`shown: 0`, withheld count stated) until the authoritative
   ten-score codebook is supplied.
2. **URL vs archive separation.** `source_url`, optional `archived_url`
   and `archive_snapshots[]` are distinct fields. An `archived_url`
   must be corroborated by a `verified_bytes`/`issuer_attested` snapshot
   entry (error otherwise; copying the live URL into `archived_url` is
   rejected). Mutable HTML captures without any snapshot raise a
   warning: the live URL is not a time-stable original.
3. **Typed cohort triggers.** `cohort.applies_to.event_type` is an enum
   (`call_opened | award_made | grant_period_started | publication_date
   | submission_date | other | unreviewed`) with `object_scope`;
   cohort `start`/`end` dateClaims must be typed `cohort_start` /
   `cohort_end` and bind to that event only. Cohort thresholds are never
   consulted by effective-date resolution (test-proven).
4. **`retrieved_at` is the only retrieval event.** Legacy
   `dateClaim.type=retrieved` is rejected in v0.3 (shape enum no longer
   contains it; an explicit semantic error fires if shape is bypassed).
   Signature (`adopted`), gazette publication (`published`) and
   attachment-update (`other`, nullable) stay distinct claim types.
   `promulgation_linked` effectiveness may derive from a gazette
   `published` claim as well as `promulgated` (documented choice for
   "in force upon publication in the official gazette").
5. **Duplicate-byte aliases.** `duplicate_of_manifestation_id` is legal
   only when both records carry non-null, equal SHA-256, reference the
   same version, and neither is a translation. `distinct_manifestations()`
   counts one underlying policy manifestation per alias group.
   Conflicting version assignments and cross-version identical hashes
   are validation errors.
6. **Provision cohort applicability is mandatory.** Every provision
   declares `cohort_applicability_status` + `cohort_ids`. `subset`
   requires ≥1 id, all of which must be cohorts of the provision's own
   version; `all_covered`/`unknown`/`not_applicable` require an empty
   array. Display mapping: `unknown` → "Unknown", never "All cohorts"
   (test-proven in public views).

## Migration notes: v0.2 → v0.3

| v0.2 (`0.2-draft`) | v0.3 (`0.3-draft`) |
| --- | --- |
| `schema_version: 0.2-draft` | `0.3-draft` (const) |
| `dateClaim.type` enum included `retrieved` | `retrieved` removed; retrieval only via `manifestation.retrieved_at` — **reject legacy `retrieved` claims on import** |
| `cohort.applies_to` free text | typed object: `event_type` enum + `object_scope` (+ optional `event_details`, `issuer_program`) |
| cohort start/end claim types loosely checked | `start` must be `cohort_start`, `end` must be `cohort_end` (errors) |
| manifestation had `source_url` only | adds `archived_url`, `archive_snapshots[]`, `duplicate_of_manifestation_id`; `retrieved_at` documented as the only retrieval event |
| duplicate hashes: same-version = implicit note | same-version duplicates should carry an explicit `duplicate_of_manifestation_id` alias (bytes must match); aliases collapse to one underlying manifestation; conflicting versions fail |
| provisions had no cohort reference | provisions gain required `cohort_ids` + `cohort_applicability_status`; subset must cite valid cohorts of the version |
| no score model | new `score_definitions[]` + `score_observations[]`, separate from provisions; no labels hardcoded, no composite until codebook supplied |
| `promulgation_linked` derived only from `promulgated` | may also derive from gazette `published` claim |
| — | `release.as_of` unchanged; semantics still open (Q13) |

v0.2 documents are **not** valid v0.3 documents (const + removed enum +
new required provision fields + new required top-level arrays); a
converter must add empty `score_definitions`/`score_observations`,
retype cohort `applies_to`, move any `retrieved` claims to
`retrieved_at`, and declare cohort applicability on every provision.

## Which v0.2 open questions these decisions resolve

Resolved: **Q1** (scores: separate `score_observations`, gated until
codebook), **Q3** (duplicate hash: explicit alias, one underlying
manifestation), **Q5** (typed cohort `event_type`), **Q6** (cohort_only
conflict rule confirmed and kept), **Q8** (`archived_url` +
`archive_snapshots` added), **Q9** (`retrieved_at` canonical; legacy
`retrieved` rejected), **Q14** (`cohort_ids` +
`cohort_applicability_status` on provisions).

Still open for the next corpus/codebook handoff: **Q2**
(`public_import_status` home), **Q4** (`authority_status` vs
`source_status` precedence), **Q7** (HTML-capture rights default),
**Q10** (bilingual versions), **Q11** (dual pagination), **Q12**
(`issuer_type: unreviewed`), **Q13** (`release.as_of` semantics),
**Q15** (null `version_id` manifestations).

## Unresolved fields (new or carried)

- **Authoritative ten-score codebook**: dimension ids, labels, scale
  anchors, `codebook_version`. Until supplied: no labels hardcoded, no
  composite, score observations withheld from all public views.
- `promulgation_linked` deriving from `published`: confirm gazette
  publication is always the intended basis, and what to do when both
  `promulgated` and `published` claims carry different values.
- `archive_snapshots.capture_status` minimum for a **public**
  `archived_url` (currently `verified_bytes`/`issuer_attested` for
  internal validity; public link policy not yet set).
- `score_observations.actor/action/object/condition` — kept nullable;
  confirm whether score observations should reuse provision semantics.
- `cohort` with unknown start (status `unknown`/`unreviewed`, null
  value) — allowed by validator; confirm intended.
- All eight open questions above (Q2, Q4, Q7, Q10–Q13, Q15).
