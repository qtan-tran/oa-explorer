## Schema / semantic mismatches found

1. **The v0.3.2 schema's Q15 conditional uses `allOf`/`if`/`then`, which
   this repo's JSON-Schema-subset shape validator does not implement.**
   Shape-only validation would PASS a `controlling_original` with null
   `version_id`. Enforced instead as a semantic error in
   `validate_v032_semantics` (test-proven). Flagged for a future full
   validator.
2. `release.as_of` changed type from `dateClaim` object (v0.3.1) to a
   plain date string (v0.3.2) — v0.3.1 fixtures are not valid v0.3.2 by
   design; the library is version-aware and older fixtures still pass
   against their own schemas.
3. Removed enum values are rejected by shape first; a semantic pre-scan
   (`validate_v032_legacy_enums`) adds the evidence-based migration
   message ("never by string mapping alone").
4. Q2 `public_import_status` deliberately has **no schema field**: it is
   internal-only, read from a local gitignored CSV, applied via
   `qc_holds`; the hold flag itself never appears in exported views.
5. No contradictions found between the v0.3.2 schema and the eight-question
   report.
