The fixture's structural scenarios (mapped to the QC workbook only in
conversation, not in the repo):

1. **Institutional policy, effective genuinely unknown** — adopted date
   attested; effective claim empty; display reads
   *"Unknown / not established"*.
2. **Call-opened cohort, no inferred effective date** — funder terms
   whose coverage runs through calls opened on/after 2021-01-01
   (`effective_date_interpretation: cohort_only`, open-ended cohort).
   Adding a valued effective claim equal to the cohort start is a
   **validation error** (test proves it).
3. **Dual award cohorts** — a 2026 notice covering a bounded legacy
   cohort (2015-05-01 through 2026-12-31) *and* an open-ended 2027-01-01
   cohort; still no general effective date.
4. **Effective on promulgation** — adopted 2023-10-09, promulgated
   2023-10-17, in force on promulgation per Art. 26
   (`promulgation_linked`); the effective *claim* stays empty; the
   reader shows the derived date with its basis.
5. **Signed approval resolution + annex** — internal-only controlling
   original with `authority_evidence` and an `ancillary` annex linked
   via `component_of_manifestation_id`; version withheld
   (provisionally reviewed). Approved claim stays `unknown`/`unreviewed`
   until the resolution is verified.
6. **Webpage modification vs publication** — mutable issuer HTML
   captures with `retrieved` date claims and `retrieved_at` distinct
   from `published`.
7. **Legal mirror duplicate hash** — same sha256 on a controlling
   original and an archive mirror of the same version: validation note,
   not an error. Cross-version or translation duplicates are errors.
8. **Explicit effective contrast case** — repository rules that state
   their own effective date.

## Public gating and display toggles

Reader views are built by `build_public_views(doc, cfg)`:

- A **version** is public only if `review.state` is
  `analyst_checked` or `independently_reviewed`.
- A **manifestation** appears only if `rights_status` is
  `public_redistribution_approved` or `link_only_approved` **and** its
  review gate passes.
- A **provision** appears only if its bound manifestation is public;
  its excerpt additionally requires
  `excerpt_rights_status: approved_for_public_export`.
- `release.public_release_approved: false` withholds every record.
- Relationships to withheld versions keep the relation type and anchor
  but name no counterpart.
- Reader views never contain source hashes, reviewer identity, review
  extent, or internal evidence pointers.

Independent display configuration (`PublicConfig` / CLI flags on
`site/build_exchange.py`):

| Switch | Default | Effect |
| --- | --- | --- |
| `--links/--no-links` | on | document links to public manifestations |
| `--downloads/--no-downloads` | off | download affordances; additionally requires `public_redistribution_approved` |
| `--excerpts/--no-excerpts` | on | excerpt text; rights-not-approved excerpts are withheld regardless, with anchor and clause analysis kept |

Withheld counts are always shown (e.g. "4 of 10 records are withheld").

## Migration note: v0.1 CSV ledger → v0.2 exchange JSON

The M1 ledger (contract v0.1) and the exchange contract are **different
artefacts**: the ledger is our internal collection store; the exchange
document is what a corpus release would hand to the explorer. A pilot
export must be converted, not merged. Sketch of the mapping:

| v0.1 (CSV ledger) | v0.2 (exchange JSON) |
| --- | --- |
| one row per entity, 9 tables | typed arrays: `countries`, `organizations`, `families`, `versions`, `manifestations`, `provisions`, `relationships` |
| `review_state` + `public_visible` flags | `review` objects (state/extent/reviewer/date/note) + `rights_status` + `release.public_release_approved` |
| date columns (`adoption_date_*`, `effective_date_*`, verbatim block) | `dates[]` of typed claims (`type`/`value`/`precision`/`status`/anchor/note); verbatim text goes to `note` |
| date *basis* column | `type` (adopted/approved/published/effective/promulgated/…) + `effective_date_interpretation` |
| `value_state` triple (value/known/absence) | union of nullable value + `status` enum + review objects; `reviewed_absence` maps to `review.state` + provision `code_status: reviewed_absence` |
| `access_status` / `excerpt_policy` on manifestations | `role` + `rights_status` (+ `excerpt_rights_status` on provisions) |
| `texts.csv` (per-field translations) | `title_original` / `title_english` on versions; `translation_english` on provisions |
| relationship table with source columns | `relationships[]` with `type` enum, evidence manifestation and anchor |
| (none) | `cohorts[]` — new concept; v0.1 had no cohort model |

Deliberately **not** converted in this slice: the ten ROARA dimension
scores and their derived means/composite have **no home in v0.2**. The
explorer must not invent one; see open questions.

## Open questions for the corpus thread

1. **Scores**: v0.2 has no field for the ten dimension scores or the
   derived family means/composite. Are they out of scope for the
   exchange (computed elsewhere), or should a `scores` block be added?
2. **`public_import_status` home**: the QC workbook's `public_import_status`
   (hold/etc.) has no schema counterpart. Is it corpus-internal only, or
   does it map to `release.public_release_approved` / rights enums?
3. **Duplicate-hash policy**: we enforce "same version + no translation
   role = legal mirror". Confirm, and decide whether a legal duplicate
   must link the copies (`component_of`?) or stay implicit.
4. **`authority_status` vs `source_status` draft overlap**: both can be
   `draft`/`unverified`-ish. Which wins when they disagree?
5. **Cohort `applies_to` structure**: currently free text. "Calls
   opened on/after", "awards made on/after" and "grant periods starting"
   are legally distinct thresholds; the string should be typed
   (enum: `call_opened` / `award_made` / `grant_period` …).
6. **`cohort_only` conflict rule**: we error when an explicit valued
   effective claim coexists with `cohort_only`. Confirm this is desired
   (it matches the call-opened-cohort QC scenario).
7. **HTML capture rights default**: `issuer_html_captured` + link-only
   is our assumption for mutable pages. Confirm default rights status.
8. **No archived/snapshot URL**: v0.1 had `archived_url` + archive
   service per manifestation; v0.2 has only `source_url`. Public links
   to mutable issuer pages need an archival-snapshot field — real gap.
9. **`retrieved_at` vs `retrieved` dateClaim**: both model webpage
   modification. Which is canonical; must they agree?
10. **Single `language` per version**: v0.1 allowed per-text languages;
    a bilingual policy needs either multiple manifestations per
    language (with roles) or a repeated field. Confirm modelling.
11. **`physical_pages` integer**: loses "physical p. 56; printed p. 53"
    (two paginations). Keep as note/anchor only?
12. **`issuer_type: unreviewed`** in the organizations enum: an
    issuer *type* should not encode review state (we gate on
    `identity_review`). Confirm removal or intent.
13. **`release.as_of` semantics**: snapshot date of the release
    contents vs publication date of the release. Clarify.
14. **Provisions lack a cohort reference**: a clause conditioned on a
    cohort must currently repeat the threshold in `condition` free text.
    Consider `cohort_id` on provisions.
15. **Null `version_id` on manifestations**: allowed by the schema; we
    treat an unrecovered lead with null binding as family-level. Is a
    required version binding intended instead?
